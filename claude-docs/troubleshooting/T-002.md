# T-002 · jsdom에서 IndexedDB를 왕복한 Blob은 Blob이 아니다

- **증상**: 화면 테스트(`FacePhoto` 등)에서 사진을 진짜로 저장한 뒤 `listPhotos`로 읽으면 **목록이 항상 빈다.** 저장은 `'ok'`로 끝나고 에러도 안 난다.
- **원인**: IndexedDB는 값을 **구조화 복제**로 저장하는데, fake-indexeddb의 복제 구현이 **jsdom의 `Blob`을 모른다** — 왕복하면 평범한 객체가 되고, `photoStore`의 어휘 검증(`p.blob instanceof Blob`)이 그걸 전부 걸러 낸다. 저장소 코드는 맞게 도는데 테스트만 빈손이다.
- **해결**: 화면 테스트에서는 `listPhotos`·`savePhoto`를 `vi.mock`으로 갈아 끼운다. 저장소 자체는 `photoStore.test.ts`가 **node 환경**에서 진짜 fake-indexeddb로 잰다(node의 Blob은 복제된다). `openPhotoDb`는 화면이 「IDB가 없으면 안내로 빠진다」로 분기하는 곳에서만 진짜를 쓴다.
- **재발방지**: 화면 테스트 파일 머리말에 이 사유를 적어 둔다 — 안 적으면 다음 사람이 「목이 게을러서 그렇다」고 읽고 진짜 왕복으로 되돌린다. restfit T-232에서 이식한 함정이라 이 계보의 프로젝트에서 반복된다. 관련: [T-003](T-003.md).
