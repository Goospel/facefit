# T-010 · 토글 라벨에 행동만 적으면 상태로 읽힌다 (그리고 디버깅이 엉뚱한 데로 간다)

- **증상**: 실기기 검증에서 「백업 켜기를 눌렀다」는 보고를 받았는데 **서버에 PUT이 안 왔다.**
  CORS를 막 고친 직후라 그쪽을 의심했고, 레이트리밋·`getBackupKey` 실패·React 클로저까지
  훑었다. 실제로는 **사용자가 버튼을 안 눌렀다** — 「기록 백업 켜기」라고 적힌 것을 보고
  **이미 켜져 있다**고 읽은 것이다. 사용자의 질문이 그대로 원인이었다:
  「화면이 "기록 백업 켜기"로 되어있으면 켜져있는거 아니야?」

- **원인**: 버튼 하나에 **행동만** 적고 상태를 안 적었다. 「켜기」는 명령으로도 상태로도
  읽히고, 둘 다 말이 된다. 게다가 이 앱에는 **성공했는지 알려 주는 표시도 없었다** —
  모든 서버 경로가 무음 폴백이라 눌러도 화면이 안 변하니, 자기가 누른 것이 먹혔는지
  확인할 방법 자체가 없었다. 두 결함이 겹쳐 「눌렀다/안 눌렀다」를 아무도 알 수 없었다.
  ⚠️ 코드 주석에는 「이 버튼은 **상태를 그린다**」고 적혀 있었다 — **주석과 코드가 어긋난 채**
  주석을 믿고 설계를 검토했다.

- **해결**: 상태와 행동을 **갈랐다.** 버튼 위에 상태 줄을 둔다:
  `기록 백업이 꺼져 있어요` / `기록 백업 켜짐 · 마지막 백업 9월 1일 21:25` /
  `기록 백업 켜짐 · 아직 백업하지 못했어요`. 마지막 줄이 두 번째 결함까지 막는다 —
  **켜 놓고 안 되는 상태**가 제일 위험한데(사용자는 지켜진다고 믿는다) 그것만 숨지 않는다.

- **후속(2026-09-01)**: 같은 날 이 컨트롤을 **「제품」 탭의 스위치**(`role="switch"` +
  `aria-checked`)로 옮겼다 — 고스트 버튼이 이질적이라는 실기기 지적이 계기였지만, 결과적으로
  **원인 자체를 구조로 없앴다**: 스위치에는 「켜기」 같은 행동 문구가 아예 없어서 라벨을
  상태로 오독할 여지가 없다. 상태 줄은 남되 역할이 바뀌었다 — 상태를 되풀이하는 대신
  **왜 켜는지**를 말하고, **켜 놓고 안 되는 상태**만 주황으로 남는다(두 번째 결함의 방어는 유지).

- **재발방지**: ① **토글은 상태를 글자로 말한다**(또는 스위치처럼 상태가 형태에 실리게 한다). 라벨만으로 상태를 유추하게 두지 않는다.
  ② **무음 폴백은 백그라운드에만 적용한다** — 사용자가 **명시적으로 누른 행동**의 결과까지
  조용하면 그건 폴백이 아니라 깜깜한 것이고, 사용자도 개발자도 실패를 못 본다.
  ③ 실기기 보고가 코드와 안 맞으면 **「그 화면이 실제로 무엇을 보여 줬는가」를 먼저 묻는다** —
  이번엔 사용자의 반문 한 줄이 코드 탐색 몇 라운드보다 빨랐다.
