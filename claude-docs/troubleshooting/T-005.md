# T-005 · Git Bash `wc -m`은 한글을 바이트로 센다

- **증상**: 콘솔 상세 설명(500자 제한)의 길이를 `wc -m`으로 쟀더니 1264가 나왔다. 실제 문자 수는 535 — 초과 판정 자체는 우연히 맞았지만 수치가 2.4배라, 반대 방향(제한 이내인데 초과로 오판해 불필요하게 줄이는)의 오류도 그대로 가능했다.
- **원인**: Git Bash 기본 C 로케일에서 `wc -m`은 멀티바이트를 해석하지 못해 `wc -c`(바이트)와 같게 동작한다. 한글은 UTF-8에서 3바이트라 수치가 부풀려진다. 글로벌 원칙 「Git Bash grep/sed 멀티바이트 무성 실패」의 wc 판이다.
- **해결**: PowerShell에서 `(Get-Content $p -Raw -Encoding UTF8).TrimEnd("`n").Length`로 측정(468자 확정 후 제출).
- **재발방지**: **한글이 든 텍스트의 글자 수 검증은 Git Bash 도구로 하지 않는다** — PowerShell `.Length`가 기본값. 에러 없이 그럴싸한 숫자가 나오는 무성 실패라, 수치가 직감(원문 길이)의 2~3배면 로케일을 먼저 의심한다.
