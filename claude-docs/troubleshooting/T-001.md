# T-001 · 이식한 파일은 CRLF, 새로 쓴 파일은 LF — 한 레포 안에서 줄끝이 갈린다

- **증상**: restfit에서 `camera.ts`·`index.css` 등을 복사해 온 직후 `grep -qU $'\r'`로 재 보니 이식 파일은 CRLF, 이 세션이 Write로 만든 `ui.ts`·`storage.ts`는 LF였다. 에러도 경고도 없다.
- **원인**: 원본 레포의 작업 트리가 CRLF로 체크아웃돼 있어 `cp`가 그 바이트를 그대로 가져오는데, 새 파일은 도구 기본값인 LF로 쓰인다. 두 출처가 한 디렉터리에 섞이는데 **줄끝은 눈에 안 보인다.**
- **해결**: `.gitattributes` 맨 위에 `* text=auto eol=lf`를 넣어 레포 전체를 LF로 잠갔다(`.ps1 -text`는 BOM 보존 때문에 그대로 예외). 첫 커밋 전에 해서 phantom diff가 안 생겼다.
- **재발방지**: **새 레포를 이식으로 부트스트랩할 때는 파일을 복사하기 전에 `.gitattributes`부터 넣는다.** 안 그러면 뒤늦게 넣는 순간 손대지 않은 파일까지 전부 변경으로 뜬다. 그리고 줄끝이 섞인 상태에서 스크립트로 제자리 치환을 하면 여러 줄 패턴이 **에러 없이 0건**이 되는데, 돌연변이 확인에서 이게 「테스트가 못 죽였다」와 구별되지 않는다(글로벌 hookify 룰 `warn-inplace-replace-crlf`가 겨누는 것이 그것이다) — 치환은 Edit 도구로 하고, 스크립트를 써야 하면 **치환이 실제로 일어났는지 프로그램이 단언**하게 한다.
