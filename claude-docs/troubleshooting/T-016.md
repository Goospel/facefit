# T-016 · `visibility: hidden`은 요소를 접근성 트리에서만 빼는 게 아니라 **이름까지 지운다**

- **증상**: 촬영 화면의 「겹쳐 보기」 칩을 겹칠 사진이 없을 때 `visibility: hidden`으로 두고
  (자리를 지켜야 셔터가 가운데 선다), 그것을 재는 테스트를
  `getByRole('switch', { name: '겹쳐 보기', hidden: true })`로 집었다. `hidden: true`를 줬는데도
  `Unable to find an accessible element with the role "switch"`로 죽는다. 덤프에는 그 버튼이
  `aria-label="겹쳐 보기"`를 달고 멀쩡히 서 있다.

- **원인**: `hidden: true`는 **역할 필터**만 푼다 — 숨은 요소도 후보에 넣어 준다는 뜻이지,
  이름을 되살려 주지는 않는다. 접근성 이름 계산(`dom-accessibility-api`)은 숨은 노드를
  가지치기하므로 `visibility: hidden`이 걸린 요소의 계산된 이름은 **빈 문자열**이고,
  `name: '겹쳐 보기'`와는 무엇을 해도 안 맞는다. 즉 `hidden: true` + `name`은 조합 자체가
  거의 항상 0건인데, 에러 문구는 「role을 못 찾았다」라고만 말해 역할 이름을 의심하게 만든다.

- **해결**: 「숨었다」를 재는 줄에서는 역할 질의를 포기하고 DOM으로 집었다 —
  `container.querySelector('[aria-label="겹쳐 보기"]')`. 대신 판별력을 두 줄로 나눠 잠갔다:
  `queryByRole('switch', { name: '겹쳐 보기' })`가 **null이어야** 하고(보이게 만드는 돌연변이가
  여기서 죽는다), `querySelector`가 **null이 아니어야** 한다(요소를 통째로 빼는 돌연변이가
  여기서 죽는다). 실측으로 둘 다 사살을 확인했다.

- **재발방지**: **접근성 질의로는 「안 보인다」를 못 잰다** — 접근성 트리는 보이는 것의 목록이라,
  숨은 것을 그 트리에서 찾으려는 시도 자체가 모순이다. 「보이는가」는 `queryByRole`의 null로,
  「자리가 남았는가」는 DOM 질의로 **따로** 잰다. 한 줄로 둘 다 재려다 `hidden: true`에 손이
  가면 이 함정이다. 반대 방향의 형제가 T-015다(그쪽은 이름이 **오염**돼서 안 맞았고, 이쪽은
  이름이 **사라져서** 안 맞는다 — 둘 다 「눈에 보이는 글자」와 「계산된 이름」을 같은 것으로
  믿은 데서 나온다).
