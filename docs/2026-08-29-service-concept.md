# 화장품 효과 관찰 서비스 구상 (가칭 facefit) — 2026-08-29

> restfit(홈트가어렵나)의 눈바디 + 고스트 엑스레이 시스템을 얼굴에 옮겨,
> **「내가 쓰는 화장품이 정말 효과가 있는가」를 사진 기록으로 관찰**하는 서비스.
> 이 문서는 사용자 구상의 1차 정리 + Claude의 추가 제언·판단 대기 목록이다. 아직 결정 문서가 아니다.

---

## 1. 이해한 구상 (사용자 발화 정리)

| # | 구상 | 비고 |
|---|---|---|
| 1 | 매일 얼굴을 찍는다 — 세안 후 또는 아침 | 눈바디와 같은 시스템, 목적만 다름 |
| 2 | **고스트 엑스레이**로 지난 사진을 반투명하게 겹쳐 **비슷한 각도**로 찍는다 | restfit 검증 완료 기술 |
| 3 | 내가 쓰는 **화장품을 조회·저장**한다 | 어떤 제품을 언제부터 쓰는지 |
| 4 | 모인 사진을 **동영상처럼 쫘라락 재생**(타임랩스) | 변화가 긍정/부정/무변화인지 한눈에 |
| 5 | 이를 토대로 **제품 추천**까지 확장 가능 | 수익화 연결 지점 |
| 6 | 토스 **쉐어링크가 화장품 프로모션을 적극적으로 민다** | 플랫폼 = 앱인토스가 자연스러움 |

### 이 서비스의 고유 가치 (Claude 해석)

핵심은 「얼굴 타임랩스」가 아니라 **사진 타임라인 위에 「제품 사용 구간」을 겹쳐 보는 것**이다.

```
사진:   ●──●──●──●──●──●──●──●──●──●
제품A:      ├─────────────┤            ← 이 구간의 얼굴 변화가 A의 관찰 구간
제품B:              ├──────────────┤
```

단순 셀피 일기 앱은 이미 있다. 「이 구간에 이 제품을 썼다」가 사진과 한 화면에 겹쳐질 때만
"효과 관찰"이 성립하고, 이것이 곧 제품 추천·재구매 쉐어링크의 근거 데이터가 된다.
**제품 기록에서 가장 중요한 필드는 이름이 아니라 「시작일(과 종료일)」이다.**

## 3. MVP 절단 제안 (v1 / v2)

### v1 — 「기록이 쌓이는 것」까지만

1. **촬영**: 고스트 엑스레이 + 하루 1장(날짜가 키 — 재촬영은 덮어쓰기, restfit 방식 그대로)
2. **제품 기록**: 수동 입력 (제품명 + 카테고리 + **시작일**, 끝내면 종료일). 조회는 내 목록 검색 정도
3. **타임랩스 재생**: 저장된 사진 순차 재생(사진 쫘라락) + 하단에 제품 사용 구간 바
4. **캘린더**: 찍은 날 마커, 날짜 탭 → 그날 사진

### v2 이후 (의도적 보류 — 지금 안 하는 이유까지)

| 기능 | 보류 이유 |
|---|---|
| 제품 추천 | 추천 근거 데이터(사용자군)가 아직 0명. 인과 주장 리스크(§5-3)도 정리 필요 |
| 외부 화장품 DB 연동·바코드 | 화해 등은 공개 API 없음. 식약처 공공데이터는 원료·기능성 중심이라 소비자 제품명 검색에 안 맞음 — v1 수동 입력으로 충분한지 먼저 검증 |
| 얼굴 자동 정렬(랜드마크) | 고스트로 찍으면 어긋남이 작다 — 타임랩스가 실제로 덜컹거리는지 보고 결정 |
| 아침/저녁 2슬롯 | 스키마가 하루 1장 전제(`date`가 키)와 충돌 — 필요가 실측되면 확장 |
| 동영상 파일 내보내기·공유 | 재생은 화면 안 순차 렌더로 충분. 파일화는 공유 수요가 보이면 |
| 클라우드 백업 | restfit과 같은 보류 — 기기 전용 원칙(§5-2)과 맞바꾼 한계로 명시 |

## 5. 제언 · 리스크 (요청받은 「추가로 제시하고 싶은 것」)

### 5-1. 최대 교란 변수는 각도가 아니라 **조명**이다

고스트 엑스레이는 각도를 잡지만 조명은 못 잡는다. 피부 톤·트러블 판독은 조명이 흔들리면
같은 얼굴도 다르게 찍힌다. 제안:

- **같은 시간대 촬영 습관화** — 앱인토스 푸시로 매일 같은 시각 리마인드(콘솔 푸시 도구 보유)
- **화면 조명**: 촬영 순간 화면을 흰색으로 꽉 채워 전면 링라이트처럼 쓰는 기법(셀피 앱 상용 기법) — 외부 조명 편차를 일부 상쇄. v1에 넣을 만큼 싸다
- 타임랩스에서 조명 편차가 심한 날은 사용자가 스스로 걸러 보게 된다 — 자동 보정은 비목표

### 5-2. 얼굴 사진은 민감정보다 — 「기기 전용」이 검수·법무 부담을 다 줄인다

- 서버 업로드 순간 개인정보(사실상 생체정보급) 처리 주체가 된다 — 처리방침·보관·파기 의무 전부
- restfit은 「사진은 기기를 떠나지 않는다, 서버 0대」로 검수를 통과했고 같은 원칙이면 이 부담이 통째로 사라진다
- 대가: 기기 변경 시 소실, 용량 상한(restfit은 365장 롤링 ≈ 70MB — 얼굴도 같은 정책이면 충분)
- ⚠️ 검수 제출 시 개인정보처리방침에 카메라·사진 항목 정합 필수(restfit에서 실측한 반려 리스크)

### 5-3. 「효과 있다」는 말은 앱이 하면 안 된다

피부 변화에는 수면·식단·계절·호르몬 등 화장품 외 변수가 많다. 앱이 「이 제품 덕분에
좋아졌다」고 단정하면 표시광고법·화장품법(의약품적 효능 표방 금지) 리스크를 앱이 진다.

- 앱의 역할 = **기록과 관찰 도구**. 판단은 화면이 아니라 사용자가 한다
- 문구 규율: 「달라진 게 보이나요?」(질문형) ○ / 「○○로 피부가 좋아졌어요」(단정) ×
- 제품 추천도 「효과 보장」이 아니라 「이 고민을 가진 사람들이 많이 쓰는」 수준의 표현으로

### 5-4. 리텐션이 곧 제품이다

이 앱의 가치는 전부 **연속 촬영**에서 나온다. 사진 3장으로는 타임랩스도 관찰도 없다.

- 매일 푸시(§5-1) + 캘린더 연속 기록 시각화(restfit 캘린더 마커 패턴)
- 첫 실행에서 가치를 미리 보여주기: 온보딩에 예시 타임랩스 1개(번들 내장 일러스트) 검토
- D+7, D+30에 「일주일 전/한 달 전과 비교」 카드 — 비교가 리워드다

### 5-5. 수익화 스케치 (쉐어링크 중심)

| 지점 | 방식 |
|---|---|
| 쓰던 제품 소진 시점 | 「다시 채울 때 됐어요」 → 쉐어링크 재구매 버튼 (restfit 기구 추천 버튼과 동일 패턴 — 대가성 문구 포함 구현 경험 있음) |
| 관찰 결과가 좋았던 카테고리 | 같은 카테고리 프로모션 제품 노출 |
| 광고(IAA) | 타임랩스 재생 전후 등 — restfit 광고 규율(기능은 광고에 양보하지 않는다) 계승 |

화장품은 소모 주기가 짧아(1~3개월) 재구매 링크의 자연 빈도가 운동 기구보다 훨씬 높다 —
쉐어링크 프로모션이 화장품에 몰려 있다는 관찰과 맞물리는 지점.

### 5-6. 경쟁과 차별점

셀피 타임랩스 앱, 피부 일기 앱은 이미 있다. 이 조합이 차별점:
**고스트 정렬(각도 재현) × 제품 사용 구간 겹침(관찰 성립) × 토스 유통(설치 마찰 0 + 쉐어링크)**.
셋 중 하나만으로는 약하고, 셋이 겹치는 앱은 못 봤다(정식 시장 조사는 안 했음 — 필요하면 별도 조사).

## 6. 기술 방향 (요약)

- restfit과 같은 스택: React + Vite 미니앱, localStorage(제품·설정) + IndexedDB(사진), 서버 0대
- 새로 만드는 것: 제품 CRUD 화면, 타임랩스 재생기(사진 순차 렌더 + 구간 바), 얼굴용 촬영 가이드 문구
- 데이터 스키마 초안: 사진 = restfit `BodyPhoto` 그대로(`date`가 키) / 제품 = `{ id, name, category, startDate, endDate? }`

## 7. 이름 후보 (앱인토스 노출명)

restfit(「홈트가어렵나」)의 질문형 작명을 계승하면:

1. **그화장품효과있나** — 서비스 정의 그 자체. 추천
2. 내얼굴이달라졌나 — 관찰 행위 중심
3. 피부가좋아졌나 — 부드럽지만 「효과 단정 금지」(§5-3)와의 거리 관리 필요

레포 디렉토리명은 `facefit`(가칭) — 이름 확정 시 그대로 둬도 무방(restfit도 노출명과 다름).
