**상태: 사용자 승인 대기(2026-09-02)** · 시안: https://claude.ai/code/artifact/593f1e2f-6585-4eb2-93a1-b66e12086901 (① ② ④ 행)
선행: [UX 1차 명세](2026-09-02-ux-switch-camera-spec.md)(머지됨 · 번들 `20260902-17`).

## 1. 원칙 — 1차에서 남은 하나

1차가 실행한 둘(「켜짐·꺼짐은 셋으로 가른다」 · 「파란 버튼은 하나」)에 더해, 이번에 실행하는 것은
**「처음 온 사람이 다음 할 일을 바로 안다」**다. 그리고 1차의 「파란 버튼은 하나」를 **화면 구조**에까지
적용한다 — 파란 자리가 **지금 할 일**을 따라 옮겨 다닌다.

| 상태 | 제품 탭의 파란 버튼 | 근거 |
|---|---|---|
| 제품 0개 | 「제품 추가」 (첫 진입 카드 안) | 한 번만 하면 되는 준비. 이게 없으면 사진에 「무엇을 쓰는 동안」이 없다 |
| 제품 ≥1 · 오늘 안 찍음 | 「오늘 얼굴 찍기」 | 매일 누르는 것. 지금 이 앱이 원하는 단 하나의 행동 |
| 제품 ≥1 · 오늘 찍음 | 없음 | 오늘 할 일이 끝났다. 「다시 찍기」는 정정이라 회색 |

기록 탭도 같다 — 파란 버튼은 「재생」 하나뿐이고, 사진이 2장 미만이면 0개다.

## 3. 제품 탭

### 3-1. 첫 진입 카드 — `products.length === 0 && !editing`

지금은 회색 글 두 줄 + 「제품 추가」 큰 버튼이고, 그 **위**에 `TodayStrip`(「찍기」 작은 파란 글자)이 선다.
처음 온 사람은 「매일 한 장」이라 배운 직후인데 화면은 등록만 권하고, 찍기는 정보 행처럼 보여 둘의
관계를 두 번 읽어야 한다.

바꾼다 — `TodayStrip`을 **걷고**, 이 카드 하나가 할 일 둘을 **번호로** 말한다:

```
┌ 카드 ─────────────────────────────┐
│ 시작은 두 가지면 돼요                │  17px/700
│ ① 쓰는 제품 등록                    │  ① = 파란 원(26px) 흰 숫자 → 「지금 할 것」
│    이름만 적어도 돼요 · 사진과 함께 기간이 남아요 │  13px text-sub
│ [ 제품 추가 ]                        │  ui.primary — 화면 유일의 파란 버튼
│ ② 오늘 얼굴 한 장                   │  ② = 회색 원(--line) text-sub 숫자
│    매일 같은 구도로 · 등록이 끝나면 이 버튼이 파랗게 바뀌어요 │
│ [ 오늘 얼굴 찍기 ]                   │  ui.secondary  (또는 §3-3 「찍은 뒤 행」)
└──────────────────────────────────┘
```

- 카드는 `ui.card`, 안은 `display: grid; gap: 16`. 번호 원은 `flex-shrink: 0; width/height: 26; borderRadius: 999; fontSize: 13; fontWeight: 700`.
- **②의 버튼 자리는 §3-2·§3-3과 같은 부품을 쓴다** — 안 찍었으면 `secondary` 톤의 찍기 버튼, 찍었으면 「찍은 뒤 행」. 제품 0개인데 사진부터 찍은 사람에게도 화면이 거짓말을 안 한다.
- 「등록이 끝나면 이 버튼이 파랗게 바뀌어요」는 **약속**이다 — 제품이 1개 생기면 카드가 사라지고 §3-2의 파란 CTA가 서므로 참이다. 이 문장은 약속이 참인 동안만 산다(3-2를 바꾸면 같이 바꾼다).
- 폼이 열리면(`editing`) 카드는 안 그린다 — 지금 빈 상태 블록과 같은 규칙. 헤더 「추가」도 지금처럼 0개일 땐 없다 → **「제품 추가」 버튼은 여전히 0개 또는 1개**(기존 테스트 규율 유지).
- `LOCAL_ONLY` 한 줄을 카드 아래 가운데 정렬로 둔다(제품 탭에는 지금 이 고지가 없다 — 첫 화면이 된 뒤로 검수자가 처음 보는 화면인데 고지가 없는 상태였다).

### 3-2. 찍기 CTA — `products.length > 0 && !todayPhoto`

`TodayStrip`(카드 + 얼굴 아이콘 + 작은 「찍기」)을 **버튼 하나**로 바꾼다:

- `ui.primary` + `display: flex; alignItems: center; justifyContent: center; gap: 8; padding: 16px 12px; fontSize: 17` · 앞에 `face` 아이콘 22px 흰색 · 글자 「오늘 얼굴 찍기」.
- `aria-label="오늘 얼굴 찍기"` — **기존 접근성 이름 그대로**(`Products.test.tsx:83`·`App.test.tsx:132`가 이 이름으로 누른다). 보이는 글자와 같으니 aria-label은 생략해도 된다.
- 위치: 헤더 바로 아래(지금 `TodayStrip` 자리). 폼이 열려 있어도 **그대로 둔다**(지금도 그렇다).
- 안내 문장 「지난 사진에 얼굴을 겹쳐 같은 구도로 찍어요」는 **걷는다** — 촬영 화면 첫 줄이 같은 말을 한다. 오늘 탭에도 남아 있다.

### 3-3. 찍은 뒤 행 — `todayPhoto`

```
[✓] 오늘 찍었어요                       [다시 찍기]
    그대로예요  ← notes[date] 있으면 VERDICT_KO, 없으면 「'오늘' 탭에서 볼 수 있어요」
```

- 행은 `ui.card` `padding: 12px 16px` · 가로 flex `gap: 10`. 체크는 22px 원(`--green`) 안 `check` 14px 흰색. 제목 15/600, 아래 13 text-sub.
- **행 전체는 버튼이 아니다** — 오른쪽 「다시 찍기」만 `ui.ghost`(글자 `--text-sub`) 버튼이고 `aria-label="오늘 얼굴 다시 찍기"`(기존 이름 유지, `Products.test.tsx:95`).
- 지금 `TodayStrip`은 두 상태 모두 행 전체가 버튼이었다. 찍은 날엔 행이 **상태 보고**이고 행동은 정정 하나뿐이라, 큰 표면을 버튼으로 두면 「또 눌러야 하나」로 읽힌다.
- 사진은 여전히 안 그린다(제품 탭이 첫 화면이 된 이유).

### 3-4. 지우는 것

`TodayStrip` 컴포넌트와 그 주석. 파일 안 새 부품 이름 제안: `StartCard`(3-1) · `ShootCta`(3-2) · `ShotRow`(3-3). 3-1의 ② 자리가 3-2·3-3을 **재사용**하므로 셋 다 같은 파일에 둔다.

## 4. 기록 탭

### 4-1. 변화 보기 카드 — `photos.length >= 2` · 달력 **위**

이 앱의 보상(얼굴이 어떻게 달라졌나)이 달력 밑 회색 「재생」에 묻혀 있고, 바로 아래 빨간 「사진 모두
삭제」가 붙어 보상과 파괴가 한 덩어리로 읽힌다.

```
┌ 카드(padding 12) ───────────────────────────┐
│ [썸네일 56×72] 얼굴 변화 보기        [▶ 재생] │
│                12장 · 8월 1일 ~ 9월 2일        │
└─────────────────────────────────────────────┘
```

- 썸네일은 지금처럼 **최신** 사진(`useObjectUrl`) · `borderRadius: 8; objectFit: cover`. 제목 15/600 「얼굴 변화 보기」. 아래 줄 13 text-sub: `{n}장 · {첫 사진 M월 D일} ~ {마지막 M월 D일}` — 지금의 「사진 n장 · 최근 M/D」를 **기간**으로 바꾼다(타임랩스가 보여 주는 것이 기간이다).
- 「재생」: `ui.primary` + `width: auto; display: flex; alignItems: center; gap: 6; padding: 11px 16px; fontSize: 15; borderRadius: 999` + `play` 아이콘 16px. 보이는 글자 「재생」 = 접근성 이름(`History.test.tsx:205` 유지).
- 위치: `h1` 바로 아래, 달력 카드 위. 달력 카드는 `marginTop: 16`.
- 달 문구 「n월 · m일 찍음」은 달력 아래 그대로.

### 4-2. 1장·0장

- **1장**: 지금 문장 「사진이 2장 모이면 재생할 수 있어요」를 **달력 아래 그 자리**에 그대로 둔다 — 누를 수 없는 것을 맨 위에 올릴 이유가 없다(`History.test.tsx:224` 유지).
- **0장**: 아무것도 없다(지금과 같다).

### 4-3. 삭제 격리

`LOCAL_ONLY` 줄 아래 `<hr>`(`ui` 관례: `border: 0; borderTop: 1px solid var(--line); margin: 24px 0 16px`)을 두고, 그 아래 「사진 모두 삭제」(`ui.ghost` 빨강 — 지금 그대로). 접근성 이름·동작 무변경.

### 4-4. `play` 아이콘

`ICONS.play = ['M8 5.5v13l10-6.5z']` — 24 그리드 스트로크 삼각형. 16px에서 한 획이라 안 뭉갠다.

## 5. 오늘 탭 — 이번엔 안 건드린다(유보 사유)

오늘 탭도 촬영 카드에 「오늘 얼굴 찍기」 파란 버튼을 갖고 있어, 2차 뒤에는 **두 탭이 같은 파란 버튼**을
갖는다. 이건 이 문서의 원칙과 충돌하지 않는다 — 원칙은 「한 화면에 하나」다. 다만 「오늘 탭의 존재 이유」
(오늘 사진 보기 · 알림 행)는 별개 질문이라 여기서 안 푼다. 2차를 실기기로 써 본 뒤 오늘 탭이 제품 탭과
겹친다고 느껴지면 그때 오늘 탭을 「오늘 사진 + 알림」만 남기는 축소를 검토한다(⏸ plan).

## 6. 접근성 · 테스트 갱신 지점

**유지되는 이름**: 「제품 추가」(0 또는 1개) · 「오늘 얼굴 찍기」 · 「오늘 얼굴 다시 찍기」 · 「재생」 · 「사진 모두 삭제」. 기존 테스트가 이 이름으로 잡으므로 대부분 **그대로 통과해야** 한다.

| 파일 | 바뀌는 단언 |
|---|---|
| `Products.test.tsx:131` | 「아직 등록한 제품이 없어요」 → 「시작은 두 가지면 돼요」 |
| `Products.test.tsx` 신규 | 제품 0개: 파란 버튼(`background: var(--blue)`)은 「제품 추가」 **하나** · 「오늘 얼굴 찍기」는 `secondary` 톤 |
| `Products.test.tsx` 신규 | 제품 ≥1·안 찍음: 파란 버튼은 「오늘 얼굴 찍기」 하나 · 「제품 추가」는 헤더 글자 버튼(배경 없음) |
| `Products.test.tsx` 신규 | 찍음: 파란 버튼 0개 · 「오늘 찍었어요」 + 「다시 찍기」 ghost · 행 전체는 버튼이 아님 |
| `Products.test.tsx` 신규 | 제품 0개·찍음: 카드 ② 자리에 「찍은 뒤 행」 |
| `History.test.tsx:212` | `/사진 2장/` → `/2장 · /` + 기간 문구 |
| `History.test.tsx` 신규 | 2장↑: 변화 보기 카드가 달력 **앞**(DOM 순서) · 「재생」이 `primary` 톤 · 1장: 카드 없음 |
| `History.test.tsx` 신규 | 「사진 모두 삭제」 앞에 `hr` |
| `Icon.test.ts` | `play` 추가 |

「파란 버튼은 하나」는 **계측 가능한 규칙**이다 — 화면의 `button` 중 `style.background`가 `var(--blue)`인 것을 세는 헬퍼를 두고, 세 상태에서 각각 1·1·0을 단언한다. 돌연변이: 찍은 뒤에도 CTA를 남기면 0이 1이 되어 죽어야 한다.
