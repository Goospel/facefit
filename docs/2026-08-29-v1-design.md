## 0. 목표 · 비목표 요약

**목표(v1)**: 기록이 쌓이는 것까지 — ① 고스트 촬영(하루 1장) ② 제품 수동 CRUD
③ 타임랩스(사진 순차 재생 + 제품 구간 바) ④ 캘린더 ⑤ 관찰 기록 1탭(포함으로 판단 — §1-1)
⑥ 최소 온보딩. 서버 0대, 사진은 기기 전용.

**비목표**: 제품 추천·AI(§5-7 계단은 v2부터) · 성분표 사진 · 얼굴 자동 정렬 · 2슬롯 촬영 ·
동영상 내보내기 · 클라우드 백업 · **두 날짜 비교 화면**(restfit `PhotoCompare` 이식 보류 —
§1-6) · 푸시 리마인드(콘솔 운영 사안, 코드 없음). 상세와 보류 이유는 §7.

### 1-1. 관찰 기록 탭 — 포함 (핵심 판단)

| 대안 | 평가 |
|---|---|
| A. v1 제외 | 코드는 제일 싸다. 그러나 v2 추천(§5-7)의 유일한 「피부 판정」 재료가 v2 출시일부터야 쌓이기 시작한다 — 추천 계단에 오르는 순간 데이터 공백이 그대로 리드타임이 된다 |
| **B. 포함, 최소 UI (선택)** | 스키마 한 줄(`date → verdict`), 화면 한 줄(버튼 3개). restfit이 완료 화면의 `feel` 1문항으로 **같은 패턴을 이미 검증**했다(선택적·건너뛰어도 정상 경로). 비용 대비 v2 재료 가치가 압도적 |
| C. 포함, 독립 탭·메모까지 | 4번째 탭과 자유 텍스트는 v1 가치가 없다 — 추천 재료는 3값이면 족하다(§5-7 「탭 1회」). YAGNI |

**배치는 촬영 저장 직후다.** 사진을 방금 찍은 순간이 「어제보다 어때 보여요?」에 답할 수 있는
유일한 순간이고, 별도 진입 동선이 0이다. 문구는 질문형(§5-3 규율): 「오늘 피부, 어때
보였나요?」. 건너뛰면 그날 기록 없음 — `undefined`가 정상 경로다(restfit `feel`과 동일).
캘린더 날짜 시트에서 그날의 답을 보여 주되, 지난날 소급 입력은 안 받는다(관찰은 그날의
눈으로만 성립한다 — 소급은 기억의 재구성이라 v2 재료의 질을 떨어뜨린다).

### 1-2. 화면 조명 — 셔터 플래시 방식

| 대안 | 평가 |
|---|---|
| A. 미포함 | 조명이 최대 교란 변수(§5-1)인데 v1에서 제일 싼 상쇄 수단을 버린다 |
| **B. 셔터 순간 풀스크린 흰색 (선택)** | 셀피 앱 상용 기법. 흰 `<div>` 오버레이 → **500ms 대기**(전면 카메라 노출 자동 보정이 따라올 시간) → 캡처 → 제거. 코드 ~15줄, 프리뷰·고스트 정렬을 방해하지 않는다(찍는 순간에만 덮는다) |
| C. 상시 흰 테두리 프레임 | 광량이 약하고, 프리뷰 면적을 깎아 고스트 정렬을 방해한다 |

- 웹뷰에서 화면 밝기 자체는 못 올린다(Screen Brightness API 없음) — 흰 픽셀이 낼 수 있는
  최대 광량이 상한이고, 그게 이 기법의 전부다. 한계로 명시한다.
- 3초 카운트다운과의 순서: 카운트 0 → 플래시 on → 500ms → 캡처 → 플래시 off. 플래시는
  1회성 정적 표시(점멸 아님)라 광과민성 규율과 무관하다.
- 끄기 토글은 v1에 안 둔다 — 조건 통제가 목적인 앱에서 조명을 끄는 선택지는 목적과 싸운다.
  불만이 실측되면 설정 한 줄로 추가한다.

### 1-3. 고스트 기준 — 「직전 사진」이 아니라 「기준 사진」

restfit `BodyPhoto.tsx` 머리말이 근거를 이미 실측으로 갖고 있다: **직전 사진을 고스트로 쓰면
하루 1~2px의 어긋남이 누적돼 한 달 뒤 구도가 딴판이 된다.** 얼굴은 전신보다 프레임 점유가
커서 누적 드리프트가 더 빨리 눈에 띈다. 구상 문서(§1-2)의 「지난 사진」은 기법 설명이지 기준
지정이 아니라고 읽고, restfit 검증 방식(목록 첫 장 = 가장 오래된 것)을 그대로 계승한다.
기준 교체도 restfit 방식 그대로 — 캘린더에서 첫 장을 지우면 다음 장이 기준이 된다.

### 1-4. 탭 구성

```
[오늘]  촬영 입구(카드 버튼) · 오늘 사진 썸네일 · 오늘 관찰 기록 표시 · 사용 중 제품 요약
[제품]  제품 목록 + 추가/수정/종료 (CRUD)
[기록]  월간 캘린더(찍은 날 마커) + 타임랩스 입구
─ 전체화면(탭 없음): 촬영(FacePhoto) · 타임랩스(Timelapse) · 온보딩(Onboarding)
```

restfit `App.tsx`의 상태 기반 라우팅(라우터·컨텍스트 0)을 그대로 쓴다 — `tab` 하나 +
전체화면은 값 하나짜리 state(`'shoot' | 'timelapse' | null`). 탭바는 **떠 있는 캡슐**(pill)
형태·수치까지 restfit 것을 복사한다 — 2회 반려로 확정된 형태다(restfit T-224).

### 1-5. 타임랩스 조작

- 진입 시 자동 재생, 프레임 = 저장된 사진 순서(빠진 날은 자연히 건너뜀), 프레임 위에 날짜 표시.
- 속도: 기본 **6fps**(166ms/장 — 한 달치 5초, 1년치 1분), 「2×」 버튼 하나로 12fps 토글.
  fps 숫자는 상수 하나(`logic/timelapse.ts`)로 두고 구현 중 실기기에서 조정한다.
- 스크럽: 네이티브 `<input type="range">`(min 0, max 사진수−1) — 커스텀 슬라이더는 안 만든다.
- 화면 탭 = 재생/일시정지 토글. 끝에 닿으면 멈춘다(루프 없음).
- **제품 구간 바**: 슬라이더 아래, 전체 폭 = [첫 사진 날짜, 마지막 사진 날짜]. 제품마다
  가로 막대 + 이름 라벨, 겹치면 줄을 나눈다(그리디 lane 배정). 현재 프레임 위치 세로선 1개.
- 사진 0~1장이면 재생 대신 안내(「사진이 2장 모이면 재생할 수 있어요」).
- blob URL은 진입 시 전부 생성(365장 × 참조라 부담 없음), 화면 언마운트에 전부 revoke —
  `useObjectUrl` 관례(만든 곳이 revoke까지)를 목록 버전(`useObjectUrls`)으로 확장한다.

### 1-6. 비교 화면 제외

restfit `PhotoCompare`는 「기준 vs 고른 날」 정적 비교다. facefit v1의 변화 열람은
타임랩스(연속)와 캘린더 시트(개별)가 담당하고, 정적 2장 비교는 §5-4의 D+7/D+30 비교 카드와
함께 v2 검토로 묶는다. 단 **「사진 모두 삭제」는 비교 화면에 있던 프라이버시 기능이라 뺄 수
없다** — 기록 탭 하단으로 옮겨 계승한다(개별 삭제는 캘린더 시트에서).

## 4. 데이터 스키마

### 4-1. 사진 — IndexedDB `facefit-photos` / store `photos`

```ts
export type FacePhoto = {
  date: string;       // todayKey() KST 'YYYY-MM-DD' — 키. 재촬영은 put 덮어쓰기(하루 1장)
  blob: Blob;
  capturedAt: number;
  width: number; height: number;
};
export const PHOTO_MAX = 365; // 롤링 — restfit과 동일 근거(쿼터·1년 전은 기준이 아니다)
```

restfit `photoStore.ts`와 동형 — 어휘 검증(`isPhoto`) · 쓰기 경계 검증 · `ok/quota/fail` 3상 ·
같은 트랜잭션 내 프루닝 · `null` DB(프라이빗 모드) 경로 전부 유지.

### 4-2. 제품 — localStorage `facefit.products`

```ts
export const CATEGORIES = ['cleanser', 'toner', 'serum', 'cream', 'sunscreen', 'mask', 'etc'] as const;
export type Category = (typeof CATEGORIES)[number];   // 표시 한글명은 별도 라벨 맵

export type Product = {
  id: string;          // newId() — crypto.randomUUID 폴백 포함(구형 웹뷰 방어)
  name: string;        // 비면 레코드 기각
  category: Category;  // 어휘 밖이면 'etc'로 강등 — 레코드는 살린다(기록은 귀하다)
  startDate: string;   // 'YYYY-MM-DD'. 형태 어긋나면 레코드 기각(구간 바가 이 형태를 전제)
  endDate?: string;    // 없으면 「사용 중」. startDate보다 앞이면 로드 시 endDate만 버린다
};
```

- **v2 확장을 막지 않는 규칙**: 로더는 필수 필드만 검증하고 **미지 필드를 보존**한다
  (`{ ...raw, category: 강등값 }` 방식 — restfit 프로필처럼 재조립해 미지 필드를 떨구지 않는다).
  v2의 `ingredientPhotoKey?`·관찰 연계 필드가 스키마 마이그레이션 없이 얹힌다.
- 상한 `PRODUCT_MAX = 200`(개인이 넘길 수 없는 수 — 쿼터 방어만 한다).
- 순수 로직은 `logic/products.ts`: `isActive(p, date)` · 정렬(사용 중 먼저, 시작일 역순).

### 4-3. 관찰 기록 — localStorage `facefit.notes`

```ts
export type Verdict = 'better' | 'same' | 'worse';
// 저장 형태: Record<string /* date */, Verdict> — 하루 1개, 재답변은 덮어쓰기
```

어휘 밖 값은 로드에서 그 키만 버린다. 사진과 독립 저장(사진을 지워도 관찰은 남는다 —
v2 추천 재료는 사진이 아니라 이 텍스트다).

### 4-4. 설정 — localStorage `facefit.onboarded`

`'1'` 하나. 온보딩을 봤는가만 기록한다 — restfit처럼 도메인 값(goal)이 그 역할을 대신할
자리가 facefit엔 없어서 명시 키를 둔다.

## 5. 설계 (모듈별)

### 5-1. 촬영 `screens/FacePhoto.tsx`

restfit `BodyPhoto.tsx`의 상태 기계를 계승하고 세 가지를 바꾼다:

1. **가이드**: 실루엣 → 얼굴 타원 + 어깨선 SVG(정밀할 필요 없음 — 「화면 세로 2/3을 얼굴로
   채우고 중앙에」를 말하는 그림이면 족하다). 사진이 1장이라도 있으면 고스트가 대신한다.
2. **플래시 캡처**: `shoot()`이 `flash` state를 켜고 `FLASH_MS = 500` 뒤 `captureJpeg` →
   플래시 off. 플래시 중 셔터·카운트다운 버튼 잠금. 흰 오버레이는 프리뷰 위 최상단
   (`position:absolute; inset:0; background:#fff`).
3. **저장 후 관찰 1탭**: `savePhoto`가 `ok`면 닫는 대신 확인 화면 자리에 「오늘 피부, 어때
   보였나요?」 + 버튼 3개 + 「건너뛰기」. 어느 쪽이든 누르면 닫는다. 답은 `facefit.notes`에.
   저장 실패(`quota`/`fail`)면 관찰 단계로 안 넘어간다 — 사진 없는 관찰만 남는 상태를 안 만든다.

카메라 실패 문구·타임아웃 10s·재연결 1회 규율·`LOCAL_ONLY` 상시 고지는 그대로다.

### 5-2. 제품 `screens/Products.tsx`

- 목록: 사용 중(활성) 섹션 + 종료 섹션. 각 행 = 이름 · 카테고리 칩 · 「D+n」(시작일부터 경과일).
- 추가/수정: 인라인 폼 하나 — 이름(text) · 카테고리(select) · 시작일(`<input type="date">`,
  기본 오늘) · 종료일(수정 시만). 네이티브 date 입력을 쓴다 — 달력 위젯은 안 만든다.
- 「오늘까지 쓰고 종료」 버튼 = `endDate = todayKey()`. 삭제는 confirm 1회(잘못 등록 정리용).
- 검색은 안 만든다 — 개인 목록은 수십 개를 넘지 않는다. 필요가 실측되면 필터 한 줄.

### 5-3. 타임랩스 `screens/Timelapse.tsx` + `logic/timelapse.ts`

순수 로직(신설 — 전부 jsdom 불필요):

```ts
export const BASE_FPS = 6;
export function frameDelay(speed: 1 | 2): number;        // 1000 / (BASE_FPS * speed)
export type Segment = { id: string; name: string; startFrac: number; endFrac: number; lane: number };
/** 제품 구간 → 0~1 분율 + lane. 범위 밖은 클램프, 전부 밖이면 제외, endDate 없음 → last까지.
 *  first === last(사진 1장)면 호출하지 않는다 — 화면이 재생 자체를 안 연다. */
export function barSegments(products: Product[], first: string, last: string): Segment[];
/** 현재 프레임 날짜의 위치 분율. 날짜 → 일수 환산은 Date.UTC 산수(calendar.ts 규칙 계승). */
export function dateFrac(date: string, first: string, last: string): number;
```

lane 배정은 그리디(시작 분율 순 정렬 → 겹치지 않는 첫 줄) — 개인의 동시 사용 제품은 몇 개
수준이라 이 이상은 YAGNI. 화면은 `setTimeout` 체인으로 인덱스 전진(재생 상태 + 인덱스 state
둘), 언마운트에 타이머·URL 정리.

### 5-4. 캘린더 `screens/History.tsx`

restfit History에서 운동 기록을 걷어낸 형태 — 월 이동 · 찍은 날 마커 1종 · 관찰 답은 날짜
칸에 작은 뱃지(가로 이동 없이 색점, 색각 대비 텍스트는 시트에서). 날짜 탭 → 바텀시트(사진 ·
관찰 답 · 「이 사진 삭제」). 하단: 타임랩스 입구 카드(최신 썸네일 + 「n장 · 재생」, 0장이면
카드 없음 — 빈 화면으로 보내는 버튼을 안 만든다) · `LOCAL_ONLY` · 「사진 모두 삭제」.

### 5-5. 온보딩 `screens/Onboarding.tsx`

한 화면, 스와이프 없음. 내용 = 검수·사용자 양쪽에 필요한 최소 3가지:

1. **무엇**: 「매일 같은 각도로 찍어, 화장품을 쓰는 동안 얼굴이 어떻게 달라지는지 관찰해요」
   (질문형 규율 — 「효과를 알려 드려요」 같은 단정 없음)
2. **어떻게**: 「아침 세안 직후, 지난 사진에 얼굴을 겹쳐 찍으면 비교가 정확해져요」
3. **프라이버시**: 「사진은 이 기기에만 저장되며 어디로도 전송되지 않습니다」 + 카메라 권한을
   촬영에 쓴다는 고지(권한 프롬프트가 뜨기 **전에** 목적을 말해 두는 것 — 검수 관점)

「시작하기」 → `facefit.onboarded = '1'`. 예시 타임랩스 일러스트(§5-4 구상)는 v1 보류 —
번들 자산 제작 비용 대비 검증 안 된 가설이다.

### 5-6. `App.tsx`

restfit 구조 그대로: `onboarded` false → 온보딩 최전방 분기 / `view: 'shoot' | 'timelapse' | null`
전체화면 / 3탭. 제품·관찰 state는 App이 들고 저장 함수와 함께 내려보낸다(restfit
`saveOwnedAnd` 패턴). 사진은 각 화면이 `usePhotos`로 직접 연다(restfit과 동일 — DB 수명을
화면 수명에 가둔다).

## 11. 리스크 · 미검증 가정

- **플래시 500ms로 노출 보정이 충분한가** — 실기기 전용 검증(태스크 10). 부족하면 상수만 조정.
- **6fps 체감** — 같은 방식. 상수 하나라 싸다.
- **appName `facefit` 가용성** — 콘솔 생성 시 확인.
- **타임랩스 365장 메모리** — blob URL은 참조라 문제없을 것으로 보나, 저사양 실기기에서
  이미지 디코드 지연으로 프레임이 덜컹일 수 있다. 문제가 실측되면 「현재±N장만 URL 유지」로
  좁힌다(설계 변경 없이 화면 내부 최적화).
- **관찰 기록의 소급 금지가 불만이 될 가능성** — 의도된 제약(§1-1)이며, v2 재료의 질을 위한
  트레이드오프로 문서에 남긴다.
