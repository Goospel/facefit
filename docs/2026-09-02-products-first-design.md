# v4-1 설계 — 첫 화면을 「제품」으로: 얼굴은 부르기 전엔 안 보인다 (2026-09-02)

> 근거: 실기기 사용 피드백(2026-09-02, 원문) — 「제일 큰 불만은 이 앱은 들어가자마자 내 얼굴이
> 보여진다는 거야. 첫 페이지는 제품 페이지였으면 해. 근데 메인페이지인 만큼 레이아웃을
> 신경써야겠지.」 시안 셋(A 오늘 한 줄 · B 대시보드 헤더 · C 목록만+플로팅 추가) 중
> **A에 C의 「n일째」 숫자 블록을 섞기로** 결정(사용자 승인 2026-09-02).
> 이 문서는 [v1 설계](2026-08-29-v1-design.md) §5(화면)의 제품 탭·오늘 탭 절을 덮어쓴다.

---

## 0. 결론 요약

- **첫 화면과 탭 첫 자리가 「제품」이다.** 탭 순서 제품 · 오늘 · 기록, 시작 탭 `products`.
  「오늘」 탭 자체는 **한 글자도 안 바뀐다** — 얼굴 사진은 그 탭에 들어가야만 보인다(§3-1).
- **「오늘 찍기」는 제품 탭 맨 위의 얇은 상태 줄로 산다**(§3-2). 사진은 안 그린다. 찍었는지와
  관찰 답만 말하고, 오른쪽은 행동(「찍기」/「다시 찍기」)이다. 아침 알림을 받고 들어온 사람이
  **한 번 눌러** 촬영으로 간다 — 매일 한 장이 이 앱의 핵심 루프라 두 번으로 밀지 않는다.
- **제품 카드는 버튼 셋을 잃고 카드 자체가 버튼이 된다**(§3-3). 왼쪽에 「n일째」 숫자 블록,
  가운데 이름과 메타 한 줄, 오른쪽 셰브론. 수정·종료·삭제는 **카드를 눌러 연 폼 안**으로
  옮긴다(§3-4). 메인 페이지에 버튼이 카드마다 셋씩 깔리면 목록이 아니라 조작판으로 읽힌다.
- **「제품 추가」는 제목 줄 오른쪽의 파란 글자 버튼**이 된다(§3-5). 목록이 비어 있을 때만
  빈 상태 블록 안의 큰 버튼으로 내려온다 — 어느 순간에도 「제품 추가」 버튼은 **하나**다.
- 「D+n」 표기는 화면에서 사라지고 **「n일째」**가 된다 — 시작일 당일이 1일째다(§3-3).
  종료한 제품은 **쓴 날수**(「28일」)를 같은 블록에 회색으로 보여 준다.
- 관찰 문구 사전(`VERDICT_KO`)이 Home·History에 **두 벌** 복사돼 있다. 세 번째 사본을 만들지
  않고 `storage.ts`의 `VERDICTS` 곁으로 **한 벌**로 올린다(§4-4).
- 새 로직은 없다. `usePhotos` · `daysBetween` · `sortProducts` · `isActive`를 그대로 쓴다.
  서버·저장 스키마·백업 블롭은 **0 변경**이다.

## 1. 목표 · 비목표

**목표**: 앱을 열면 제품 목록이 보이고, 얼굴 사진은 「오늘」 탭에 들어가야 보인다. 제품 탭은
메인 페이지답게 **읽는 화면**이 된다(카드에 조작 버튼이 없다). 하루 한 장 촬영 동선은
**한 번 누르기**로 유지한다.

**비목표(이번에 안 한다)**:
- 「오늘」 탭 레이아웃 변경. 사진 크기·위치·「쓰는 중」 칩·알림 행 전부 그대로.
- 연속 기록 일수·이번 달 장수 같은 **새 통계**(시안 B). 계산 로직이 새로 필요하고 이번 불만과
  무관하다.
- 플로팅 추가 버튼(시안 C). 탭바 캡슐 위에 원이 하나 더 뜨면 토스 가이드의 「떠 있는 탭바」와
  경합한다.
- 카드 스와이프 액션·길게 누르기 메뉴. 웹뷰에서 제스처는 스크롤과 싸운다.
- 카테고리별 그룹·정렬 옵션. 개인 목록은 수십 개를 넘지 않는다(v1 §5-2).

## 2. 지금 상태 (코드 실측)

- `App.tsx` — `TABS` 순서 home · products · history, `useState<Tab>('home')`. 오늘 탭이 곧
  첫 화면이라 **오늘 찍은 사진이 화면 맨 위 가장 큰 표면**이다(Home 머리말이 그렇게 설계했다).
- `Products.tsx` — 맨 위 full-width 파란 「제품 추가」 → 사용 중 · 종료 섹션 → 출처 캡션 →
  백업 스위치. 카드(`Row`)마다 「수정 · 종료 · 삭제」 **버튼 셋**이 한 줄로 깔린다.
  기간은 사용 중이면 `D+${daysBetween(start, today)}`(시작 당일 D+0), 종료면 `8월 1일 ~ 8월 28일`.
- `Home.tsx` — 사진 카드 · 「쓰는 중 n」 칩 · 알림 행 · `LOCAL_ONLY`. `VERDICT_KO`를 자체 보유.
- `History.tsx` — `VERDICT_KO`를 **또** 자체 보유(같은 세 문장).
- `Icon.tsx` — `face` · `bottle` · `calendar` 셋. `Icon.test.ts`가 이름 집합을 그대로 잠근다.
- 테스트가 거는 버튼 이름: `제품 추가` · `${name} 수정` · `${name} 종료` · `${name} 삭제` ·
  `오늘 얼굴 찍기`(App.test — 오늘 탭에서 촬영 진입). `App.test`의 「시작하면 오늘 탭으로
  들어간다」가 시작 탭을 잠근다.

## 3. 결정

### 3-1. 탭 — 순서와 시작

`TABS`를 **제품 · 오늘 · 기록**으로, 시작 탭을 `'products'`로. 라벨·아이콘은 그대로다.
전체화면(`view`)을 닫으면 보던 탭으로 돌아오는 규칙도 그대로라, 제품 탭의 상태 줄에서 촬영을
열고 닫으면 **제품 탭으로** 돌아온다.

「오늘」 탭은 안 건드린다. 이름을 바꾸거나 사진을 줄이는 것은 이번 불만의 답이 아니다 —
불만은 「**부르지 않았는데** 보인다」이지 「보인다」가 아니다.

### 3-2. 오늘 상태 줄 — 제품 탭 맨 위

제목 줄 바로 아래, 알림 행·백업 행과 **같은 가족**(카드 + 가로 flex + 오른쪽 행동 글자)이다.
사진은 **절대 안 그린다.**

| 상태 | 왼쪽 | 제목 | 부제 | 오른쪽(행동) | 접근성 이름 |
|---|---|---|---|---|---|
| 오늘 사진 없음 | `face` 아이콘(파랑) | 오늘 아직 안 찍었어요 | 지난 사진에 얼굴을 겹쳐 같은 구도로 찍어요 | **찍기** | 오늘 얼굴 찍기 |
| 오늘 사진 있음 · 관찰 답 있음 | `face` 아이콘(파랑) | 오늘 찍었어요 | 좋아졌어요 / 그대로예요 / 나빠졌어요 | 다시 찍기 | 오늘 얼굴 다시 찍기 |
| 오늘 사진 있음 · 답 없음 | 〃 | 오늘 찍었어요 | '오늘' 탭에서 볼 수 있어요 | 다시 찍기 | 〃 |

- **행 전체가 버튼**이고 두 상태 모두 `onShoot`을 부른다(행동 하나). 「다시 찍기」가 덮어쓰기임은
  Home의 같은 문구가 이미 가르친다. 「보기」로 오늘 탭에 보내는 안은 기각 — 한 행에 행동이 둘이면
  라벨을 읽어야 누를 수 있다.
- 부제의 관찰 문구는 §4-4의 `VERDICT_KO` 한 벌에서 온다.
- 「오늘 사진」 판정은 Products가 **직접 `usePhotos()`를 연다**(App 설계 §1-4 — 사진 DB 수명은
  화면 수명에 가둔다). DB가 열리기 전 한 프레임은 「안 찍었어요」로 뜰 수 있다 — Home이 첫
  화면이던 지금과 같은 깜빡임이라 **받아들인다**(스켈레톤을 만들 만큼 길지 않다).
- 이 줄은 **폼이 열려 있어도 그대로 있다.** 등록하다가 촬영으로 새는 사람은 드물지만, 줄이
  사라졌다 나타나면 화면이 흔들린다.

### 3-3. 제품 카드 — 읽는 카드

카드 전체가 `<button>`(접근성 이름 `${name} 수정` — 지금 테스트가 거는 이름 그대로).
누르면 그 제품의 수정 폼이 열린다. 안에 다른 버튼은 없다.

```
┌──────────────────────────────────────────┐
│ ┌────┐  토리든 다이브인 세럼              › │
│ │ 42 │  [세럼] 토리든 [미백] [주름개선]        │
│ │일째│                                       │
│ └────┘                                       │
└──────────────────────────────────────────┘
```

- **숫자 블록**(왼쪽, 44×44, radius 10, 세로 정렬 가운데):
  - 사용 중: 배경 `--blue-soft`(신설 · `#e8f3ff`), 글자 `--blue`. 큰 숫자 = `daysBetween(start, today) + 1`
    (16px/700), 아래 「일째」(10px). **시작일 당일이 1일째다** — 「0일째」는 말이 안 된다.
  - 종료: 배경 `--bg-sub`, 테두리 `--line`, 글자 `--text-sub`. 큰 숫자 = `daysBetween(start, end) + 1`,
    아래 「일」. 끝난 제품의 숫자는 **자라지 않는다**(지금 규율 유지).
- **가운데**: 이름(15px/600, 종료면 `--text-sub`) + 메타 한 줄(flex-wrap · gap 6):
  카테고리 칩 → (mfds가 있으면) 업소명 텍스트 · 기능성 칩들 · SPF/PA 칩 → (종료면) `8월 1일 ~ 8월 28일`
  텍스트(12px `--text-sub`). 기존 `MfdsMeta`의 내용·규율(§v2-2 4-2 명사만)을 그대로 이 줄에 편입한다.
- **오른쪽**: `chevron` 아이콘(신설 · `--text-weak`). 카드가 눌린다는 유일한 신호라 장식이 아니다.
- 「D+n」 문자열은 이 변경으로 코드에서 사라진다.

### 3-4. 폼 — 종료·삭제의 새 집

`ProductForm`은 그대로이되 **수정일 때만** 취소·저장 줄 아래에 한 줄이 더 붙는다:

- 「오늘까지 쓰고 종료」(접근성 이름 `${name} 종료` · 사용 중일 때만) — 지금의 `endToday`
  (종료일 = 오늘, 오늘 포함)를 그대로 부르고 폼이 닫힌다.
- 「삭제」(빨강 · 접근성 이름 `${name} 삭제`) — 지금의 `remove`(confirm 1회)를 그대로 부른다.

종료일 칸이 있는데 버튼을 두는 이유: 네이티브 날짜 피커에서 오늘을 고르는 것은 세 번 누르기,
버튼은 한 번이다. 추가 폼에는 이 줄이 없다(아직 없는 제품을 종료·삭제할 수 없다).

### 3-5. 제목 줄과 「제품 추가」

- 제목 줄: 「제품」(h1) 왼쪽, 오른쪽에 파란 글자 버튼 **「추가」**(접근성 이름 `제품 추가`,
  `ui.ghost` + `--blue`). 폼이 열려 있는 동안은 **숨긴다**(두 개를 동시에 열 수 없다).
- 목록이 비어 있고 폼도 닫혀 있으면: 제목 줄의 「추가」를 **숨기고**, 빈 상태 블록(지금 문구
  그대로) 아래에 `ui.primary` **「제품 추가」**를 둔다. 첫 사용자가 놓칠 수 없어야 한다.
- 따라서 화면에 「제품 추가」 이름의 버튼은 **항상 0개 또는 1개**다 — 테스트가 그대로 잠근다.

### 3-6. 화면 순서(위→아래)

제목 줄 → 오늘 상태 줄 → (폼) → (빈 상태) → 사용 중 → 종료 → 출처 캡션 → 백업 스위치.
백업 스위치·출처 캡션·1회 제안 카드는 위치·문구 **0 변경**.

## 4. 구현 명세

### 4-1. `App.tsx`

- `TABS` 순서 교체, 초기 `tab` `'products'`.
- `<Products>`에 `notes`와 `onShoot={() => setView('shoot')}`를 추가로 내린다. `Home`의 props는 그대로.

### 4-2. `Products.tsx`

- props: `notes: Notes` · `onShoot: () => void` 추가.
- `usePhotos()`로 `photos` → `todayPhoto = photos.find(p => p.date === date)`.
- `TodayStrip`(신설 함수 컴포넌트, 파일 안) — §3-2 표 그대로.
- `Row` → `Card`: `<button aria-label={`${name} 수정`}>` + `DayBlock` + 메타 줄 + `Icon chevron`.
  `MfdsMeta`는 메타 줄의 일부로 흡수(별도 컴포넌트를 남기든 인라인하든 구현 재량).
- `ProductForm`에 `onEnd?: () => void` · `onRemove?: () => void` 추가. `initial`이 있고 핸들러가
  있을 때만 §3-4의 줄을 그린다. `onEnd`는 `isActive(initial, today)`일 때만.
- 제목 줄 `display:flex` + 오른쪽 「추가」. 빈 상태 블록에 primary 「제품 추가」.

### 4-3. `Icon.tsx` · `index.css`

- `ICONS.chevron: ['M9 6l6 6-6 6']` — 20px 그리드에서 획 하나. 머리말 규율(획을 더 넣지 않는다) 준수.
- `:root`에 `--blue-soft: #e8f3ff;` — 토스의 연파랑 칩 배경 톤. 주석에 「숫자 블록 배경」 명시.

### 4-4. `VERDICT_KO` 한 벌로

- `storage.ts`의 `VERDICTS` 바로 아래에 `export const VERDICT_KO: Record<Verdict, string>`
  (`better: '좋아졌어요'` · `same: '그대로예요'` · `worse: '나빠졌어요'`).
- `Home.tsx` · `History.tsx`의 자체 사본을 지우고 import. `FacePhoto.tsx`의 선택지 배열은
  구조가 달라(verdict+label 쌍) 이번엔 안 건드린다 — 문장만 같으면 된다.

### 4-5. 안 바뀌는 것

`Home.tsx`(사전 import 외) · `History.tsx`(사전 import 외) · `FacePhoto.tsx` · `Timelapse.tsx` ·
`Onboarding.tsx` · `Restore.tsx` · `storage.ts`의 스키마 · `logic/*` · 서버.

## 5. 테스트 (TDD — Red를 먼저 본다)

**바꾸는 기존 테스트**
- `App.test` 「시작하면 오늘 탭으로 들어간다」 → **제품 탭**으로(제품 h1이 보이고 오늘 h1은 없다).
  `오늘 얼굴 찍기`로 촬영에 들어가는 케이스는 이제 **제품 탭의 상태 줄**을 누르게 된다 —
  이름이 같아 테스트 본문은 대체로 그대로 통과해야 한다. 안 그러면 그 자체가 신호다.
- `Products.test` 「오늘까지 쓰고 종료」·「제품 삭제」 — `btn('토너 수정')`으로 폼을 **연 뒤**
  `토너 종료`/`토너 삭제`를 누른다. 「이미 종료한 제품에는 그 버튼이 없다」는 폼을 연 뒤 확인.
- `Icon.test` 「탭 셋이 모두 있다」 → 이름 집합에 `chevron` 추가(제목도 「탭 셋 + 셰브론」으로).
- `Products.test`의 `D+` 문자열 기대가 있으면 「n일째」로.

**새로 거는 테스트**
- 탭: 렌더 직후 활성 탭(`aria-current`)이 「제품」이고 탭 순서가 제품 · 오늘 · 기록.
- 상태 줄: 사진 없음 → 「오늘 아직 안 찍었어요」+ 버튼 이름 `오늘 얼굴 찍기`가 `onShoot`을 부른다 ·
  사진 있음+답 → 「오늘 찍었어요」+ 답 문구 · 사진 있음+답 없음 → 「'오늘' 탭에서 볼 수 있어요」 ·
  **어느 상태에도 `<img>`가 없다**(이 설계의 존재 이유를 잠근다).
- 숫자 블록: 시작일 = 오늘 → 「1」「일째」 · 41일 전 시작 → 「42」 · 8/1~8/28 종료 → 「28」「일」 ·
  종료 카드는 오늘이 바뀌어도 숫자가 같다.
- 카드: 카드 안에 버튼이 **하나뿐**(카드 자체) · 누르면 수정 폼 · 폼에 `${name} 종료`·`${name} 삭제`.
- 추가 버튼: 제품 있음 → `제품 추가` 1개(제목 줄) · 비어 있음 → 1개(빈 상태 블록) · 폼 열림 → 0개.
- `VERDICT_KO`: storage에서 export되고 세 값이 정확히 그 문장(옛 사본이 지워졌는지는 import
  경로가 컴파일로 잠근다).

**검증 절차**: `npm test` 그린 → `npm run build`(tsc 포함 — 테스트가 못 잡는 타입 오류를 잡은
전례가 v3-1에 있다) → 번들 업로드 → 실기기: 첫 화면이 제품 · 상태 줄 누르면 카메라 · 닫으면
제품 탭 복귀 · 카드 누르면 폼 · 폼에서 종료/삭제 · 「오늘」 탭에서 사진 그대로.

## 6. 리스크 · 판단 근거

- **「오늘」 탭이 덜 열린다.** 관찰 답은 촬영 직후 카메라 화면에서 받으므로 기록엔 영향이 없다.
  「쓰는 중」 칩과 알림 행이 덜 보이는데, 알림은 1회 설정이고 칩은 제품 탭이 더 잘 말한다.
  이 탭이 비어 가면 다음 계단에서 정리한다 — 이번엔 손대지 않는다(비목표).
- **카드 전체가 버튼이라 스크롤 중 오터치**로 폼이 열릴 수 있다. 폼은 취소 한 번으로 닫히고
  저장 전엔 아무것도 바뀌지 않는다. 삭제는 confirm이 지킨다.
- **1일째 vs D+0** — 숫자가 하루씩 커진다. 라이브 사용자는 사용자 본인뿐이고 기록값은 안 바뀐다
  (표시만). 타임랩스 구간 바는 `daysBetween` 비율이라 무관.
- **usePhotos가 제품 탭에서 열린다** — 지금 오늘 탭이 하던 일이라 부하는 같다. 탭을 오갈 때마다
  열고 닫는 것도 지금과 같다.
- **`--blue-soft` 대비** — `#e8f3ff` 위 `#3182f6`은 대비 약 3.3:1로 **큰 글자(16px/700) 기준 AA**
  (3:1)를 넘는다. 「일째」(10px)는 정보가 큰 숫자에 있어 보조 텍스트로 본다. 실기기에서 흐리면
  글자를 `--blue-dark`로 내린다(대비 4.6:1).
