# 한국 화장품 제품 데이터 API 리서치 (2026-08-29)

> v2 계단([구상 §5-7](2026-08-29-service-concept.md))의 「제품 검색·자동완성·성분 대조」 재료 조사.
> 조사 계기: v1 검수 준비 완료 후 다음 계단 검토. 결론은 v1에 반영 없음 — v2 설계의 입력이다.
> 후속: [2026-08-30 비기능성 제품 커버리지 리서치](2026-08-30-product-coverage-research.md) — 상업 검색 API·OBF 실측·기존 앱 DB 구축 방식.

## 결론 3줄

1. **「한국 출시 화장품 전체」의 제품 단위 공개 API는 존재하지 않는다** — 화장품은 품목
   허가·신고제가 아니라서(책임판매업자 보고는 협회 경유·비공개) 전 제품 공적 등록부 자체가 없다.
2. **1순위 재료는 식약처 「기능성화장품 보고품목」 API** — 무료·진짜 API·제품 단위·계속 갱신
   네 조건을 유일하게 다 만족(20만 건). 단 커버리지가 기능성(미백·주름·자외선 등)까지다.
3. **코리안넷(유통상품 표준DB)은 데이터 질은 최고지만 open API가 아니다** — 바코드 건당(GTIN)
   유료 협의제. 개인 사이드 프로젝트 수지로는 후순위.

## v2 계단 반영 (구상 §5-7 기준)

- **1단계(성분 사전 번들 내장, 서버 0)**: 원료성분정보(②)를 정적 스냅샷으로 가공해 번들 내장.
- **2단계(성분표 사진 AI 판독)**: 판독 결과를 ②로 대조·정규화. 프록시 서버가 이때 생기므로
  **①(보고품목)도 같은 프록시에 얹어 제품명 자동완성**을 함께 살린다 — 20만 건은 번들에
  못 싣고 런타임 직호출은 서버 0 원칙과 충돌하므로, 프록시 없는 동안은 자동완성도 없다.
  (축소 대안: 인기 품목만 추린 정적 스냅샷 — 효용 대비 관리 비용을 그때 판단.)
- **3단계(추천 + 쉐어링크 매칭)**: 병목은 API가 아니라 쉐어링크 카탈로그 조회 수단(§5-7 그대로).
- **바코드 스캔 등록**: 코리안넷 없이는 성립하지 않고, 있어도 유료 — 계단에 올리지 않는다.
  단가 문의 후 수지가 맞으면 그때 별도 판단.
